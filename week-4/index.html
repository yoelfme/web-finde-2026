Type selector

Matches every element of a tag name. p { color: red }

Class selector

Reusable hook, the workhorse of any stylesheet. .btn { padding: 1rem }

ID selector

Unique and very specific. Use sparingly. #title { font-size: 3rem }

Attribute selector

Matches on attributes and their values. [data-status="testing"] { color: gold }

Child combinator

Only direct children. nav > ul { display: flex }

Adjacent sibling

The element immediately after another. h2 + p { margin-top: 0 }

General sibling

Any later sibling. Powers every checkbox trick on this page. input:checked ~ .panel { display: block }

Negation

Everything except the argument. li:not(:last-child) { border-bottom: 1px solid }

Parent selector

Styles an element based on its contents. label:has(input:checked) { color: cyan }

Structural pseudo class

Positional matching with a formula. tr:nth-child(2n) { background: #111 }

How the cascade decides

When two rules touch the same property the browser compares origin, then layer, then specificity, then document order. Inline styles beat selectors, and !important flips the whole comparison on its head, which is exactly why it should stay a last resort. This paragraph is laid out with the multi column properties and its first letter is styled with a pseudo element, so the drop cap costs no extra markup at all. Cascade layers give you a way to order whole blocks of CSS on purpose instead of fighting specificity by accident.

Do I need JavaScript for any of this?

No. Tabs, the theme switch, the mobile menu, the accordion and the rocket launch are all state held by checkboxes and radio buttons and read back with :checked.

Why custom properties instead of a preprocessor?

Custom properties live in the cascade, so they can be redefined per theme, per media query or per component and everything downstream updates instantly.

How is the layout responsive?

Mostly without media queries: grid-template-columns: repeat(auto-fit, minmax(...)), clamp() typography and flex wrapping. Media queries only handle the navigation and a few spacing tweaks.

What about motion sensitivity?

Every animation is disabled inside a @media (prefers-reduced-motion: reduce) block.
